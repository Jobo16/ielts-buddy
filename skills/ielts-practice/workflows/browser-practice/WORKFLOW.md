# 浏览器刷题

## 核心规则

本地 Agent 选择，IELTS Buddy 提供事实和浏览器交接。不要把“题库里有什么”误写成服务端对学习者的推荐。

## 开始流程

1. 判断用户是否已经明确要开始：例如“我要刷题”“开始一组阅读”“继续上次听力”。
2. 有 MCP 时，先读取近期练习；存在未提交 session 时，优先说明可恢复的题组、已答数量和恢复链接。不要把未完成 session 自动说成唯一推荐。
3. 需要新题时，使用最小数据集：
   - 用户提出结构化筛选词时，先调用 `ielts_practice_list_taxonomy`，再把返回的精确 `tagIds` 传给 `ielts_practice_search_parts`。
   - 否则直接调用 `ielts_practice_search_parts`，最多取六个候选。
   - 需要根据已有证据做判断时，再读取学习画像或学习事件。证据不足时如实说明是在做诊断练习。
4. 本地 Agent 从候选中选择一个精确 `partId`：
   - 用户已明确要开始时，可直接创建该题组的 session。
   - 用户只是在浏览或比较时，最多展示三个候选，等待其选择。
5. 调用 `ielts_practice_start_session` 时只能传 `{ partId }`。把返回的 `launchUrl` 作为唯一正式练习入口，并保留 `sessionId` 以便完成后回读。
6. 将 `launchUrl` 输出为可点击链接；支持 Markdown 的客户端使用标准外链语法，链接文本为“开始练习”、链接地址为返回的 `launchUrl`。不得由 `partId`、`sessionId` 或网站域名自行拼接链接。
7. 用户打开链接时：已有 IELTS Buddy 网页登录态则直接进入本次练习；没有登录态则网站跳转至登录页，并在登录后回到同一练习。用户必须登录创建该 session 的同一 IELTS Buddy 账号；链接本身不是可分享的授权凭证。
8. 明确告诉用户：在浏览器完成作答后回复“已完成”或带回具体问题。

## 输出形状

```text
这一组：<标题>
题库事实：<科目>｜<题数>｜<难度>｜<是否练过>
我的判断：<一条基于用户目标或已读记录的理由；证据不足时说明是诊断练习>
开始练习：显示“打开本次练习”的可点击链接，地址为 <launchUrl>
完成后：回复“已完成”，我会读取本次结果并带你复盘。
```

## 无 MCP 降级

说明无法读取 IELTS Buddy 题库或历史，不要编造候选。提供：

```text
https://ieltsbuddy.igocn.cn/practice
```

这个入口只会打开刷题中心，不能定位到一组由 MCP 创建的精确练习。若用户提供了文章、题目或答案，仍可按本地能力协助练习或复盘。

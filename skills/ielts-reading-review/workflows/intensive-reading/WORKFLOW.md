# 四步精读

## 核心规则

先保留一次浏览器限时作答，再用同一 session 的事实做精读。不要提前给答案，不要把整篇文章复制回聊天，也不要把“读完了”当作掌握证据。

## 输入

优先使用已提交的 IELTS Buddy 阅读 session：

1. 调用 `ielts_practice_read_session` 确认 `submitted` 状态。
2. 调用 `ielts_practice_read_review({ sessionId, scope: "incorrect", includeMaterial: true })`。
3. 材料被截断、没有 session 或用户仍在作答时，说明缺少什么；不要编造证据或答案。

首次尚未作答时，交回 `$ielts-practice` 的浏览器入口完成限时练习。浏览器负责计时与提交，本地 Agent 不在聊天中重建整套题。

## 四步

1. **保留首做事实**：简要记录用时、正确率和错题编号。只把一次结果当作当前诊断样本。
2. **定位证据**：每道错题只引用必要的原文句或短语，建立“题干表达 → 原文表达”的同义替换桥；判断题必须区分明确矛盾与信息缺失。
3. **拆一处阻塞**：从错题附近选择至多两处真正阻塞理解的长难句，说明主干、修饰关系和该句如何影响答案定位。不要对整篇文章做泛化语法讲义。
4. **立即再测**：为每道题生成一个短微练习，例如遮住原文复述同义替换、重做一题定位、或改写一个限定词。用户作答后再给答案与反馈。

## 错题词汇

只从本次证据中选择 1–3 个可迁移词块。用户明确要求“收进词汇本”后，调用 `ielts_vocabulary_personal_add`：

```text
sourceType: practice
sourceId: practice_session:<sessionId>
sourceTitle: <session title>
context: <本次原文中的必要短句>
```

词义、搭配和是否值得收录由本地 Agent 判断；服务端只保存调用方提供的词汇数据。

## 输出

```text
本次精读：<题组与错题数>
首做事实：<正确率、用时>
先修这一题：<题号>
证据桥：<题干表达 → 原文表达>
阻塞点：<一句结构或逻辑>
现在复练：<一个可回答的微练习>
```

最后只给一个下一动作。需要完整错题文档时，再按“阅读复盘”生成 Evidence Map DOCX。

# 口语覆盖图

## 目标

把学习者真实、记得住的经历映射到一批明确的 Part 2 cue card，找出真正的覆盖缺口，再进入逐题练习。它不是押题、万能模板或背诵答案。

## 输入

需要以下任一题目来源：

- 学习者粘贴的 cue card 列表；
- 通过 IELTS Buddy 题库读取到的精确题目；
- 学习者已经保存的口语素材。

若题目来自题库，先用 `ielts_practice_list_taxonomy`、`ielts_practice_search_parts` 或 `ielts_practice_read_part` 读取，再由本地 Agent 选定题目。不要把题名或泛标签当作题目来源，也不要要求服务端匹配话题。

先收集 3–5 个真实经历。每个经历只需：人物/地点、发生了什么、一个具体细节、结果或感受。缺少的细节必须标记为待学习者确认，不能伪造成个人经历。

## 建图

1. 为每段经历建立一张故事卡：
   - `事实锚点`：人物、时间、地点、行动、结果；
   - `可调整角度`：可强调的人物、地点、技能、改变或感受；
   - `不能套用`：会违背题目限定的情况。
2. 逐道读取 cue card 的全部 bullet points 和限定词。
3. 为每题标记一个状态：
   - `直接覆盖`：同一经历自然回应全部要点；
   - `可调整`：能回应，但必须明确改变叙述角度；
   - `未覆盖`：缺少真实内容或无法回应关键限定。
4. 每道 `可调整` 题写出不超过两项改法，例如“把重点从地点转为与朋友共同完成的事”。不要只因话题词相似就算覆盖。
5. 按“最接近考试、最难改编、最有价值补新故事”的顺序，挑 1–2 个未覆盖题作为下一步。

## 覆盖表

```text
本轮题目：<N> 道
可用覆盖：<直接覆盖 + 可调整>/<N>

| Cue card | 主故事 | 状态 | 必须调整 | 风险 |
| --- | --- | --- | --- | --- |
| <精确题目> | <故事卡> | 直接覆盖/可调整/未覆盖 | <一项调整或—> | <一个限定词风险或—> |
```

只有题目列表完整时才给出覆盖比例。这个比例只描述当前列表，不能声称预测了真实考试题目。

## 练习交接

1. 从一张 `直接覆盖` 故事卡选一题，要求学习者先用自己的话完成 60–90 秒回答。
2. 再用同一故事切换一张 `可调整` 题，要求学习者明确说出改了什么角度。
3. 交给 [口语教练](../speaking-coach/WORKFLOW.md) 逐题反馈；不要一次生成所有题的完整英文答案。

## Part 3 延伸

只有学习者想继续练 Part 3 时，才从已经覆盖的 Part 2 主题提取一个可讨论的问题。用“立场 → 原因 → 例子 → 限制或对比”组织 2–4 句回答，再交给口语教练追问。它是主题迁移练习，不是对考题的预测。

## 保存边界

只有用户明确要求保存且 MCP 接受调用方提供的精确 `question_links`、故事和素材字段时，才调用 `ielts_speaking_materials_create` 或 `ielts_speaking_materials_update`。保存的是本地 Agent 已完成的映射，不是让服务端继续串题或生成答案。

## 输出

```text
已有故事：<标题列表>
本轮可用覆盖：<x>/<n>
先练：<一题 + 主故事>
切换练习：<一题 + 需要改变的角度>
待补故事：<最多两项>
```

# 证据到下一步

> 当当前学习任务需要本方法时按需读取。脚本命令中的 `scripts/` 相对于本 Skill 根目录；执行时解析为安装目录中的绝对路径。

## 目标

把刚完成的学习结果变成一个可执行、可验证的下一任务。先解释依据，再给下一任务；用户已明确要求保存时直接写入 IELTS Buddy 待办。

## 读取最小证据

1. 优先使用当前对话中刚产生的产物：已提交 session、精读/精听结论、词汇卡结果、口语覆盖图、写作提纲或批改报告。
2. 若是阅读或听力 session，先调用 `ielts_practice_read_session` 确认已提交，再调用 `ielts_review_read_snapshot`，默认 `scope="incorrect"`、`includeMaterial=false`。
3. 需要了解已有承诺时，使用 `ielts_study_todos_search` 按关键词、日期范围或精确 id 检索；它们只返回用户已有任务，优先顺序由本地 Agent 和证据决定。
4. 只有当前决策依赖长期历史时，读取学习快照或 `ielts_learning_pull_events`。没有证据时转入最小诊断，不臆测薄弱项。
5. 按 [跨 Skill 交接](../cross-skill-handoffs.md) 判断哪些结果能作为证据。

## 选择规则

按以下优先级只选一个动作：

1. 用户明确标记未完成或上次实际回答错误的复习；
2. 有明确错题证据、且能在本次完成的精读/精听修复；
3. 已开始但未完成的学习任务；
4. 口语覆盖图中的一个缺口或需要切换角度的 cue card；
5. 写作提纲对应的一篇初稿或一个主体段；
6. 证据不足时的最小诊断。

不要把单次错误、提纲完成或任务打开当作能力变化。词汇任务必须源自已保存的词或用户明确要求收录的词。

## 任务草案

每次输出：

```text
依据：<一个可核对事实；没有则写“证据不足”>
现在做：<单一动作>
做法：<最多三步>
完成标准：<可带回来的答案、session、草稿或录音转写>
预计投入：<用户给出的时间，或“不预设”>
```

例子：

- 阅读错题 → “用本次第 6 题完成一次证据桥微练习，并重做定位。”
- 听力拼写错 → “回放答案附近片段，先预测单复数，再独立拼写答案。”
- 口语可调整题 → “用同一故事回答下一张 cue card，并在开头明确切换叙述角度。”
- 写作规划 → “按已定的 P1 论点写一个完整主体段，保留例子与结果句。”

## 写入计划

如果用户没有明确要求保存，直接等待完成结果，不调用待办写工具。

用户已明确要求保存时：

1. 使用明确的任务标题；日期、时间、提醒均可省略，只有用户给出具体时刻才填写 time。
2. 读取 [跨 Skill 交接](../cross-skill-handoffs.md) 的“计划写入”约束。
3. 调用 `ielts_study_todos_create`，把事项放入 items 数组。
4. 有精确内容时复用检索结果的 contentRef；普通精读、写作和口语任务可以不关联内容。
5. 返回写入后的真实任务，不声称未验证的训练已经完成。

不要因生成了任务草案而写入 `ielts_learning_push_events`。只有客观作答、用户提交的输出或本地 review 的实际结果才可以形成学习证据。

## 完成后的交接

- 浏览器客观题提交后，交给 `$ielts-practice` 的结果复盘，再回到本工作流。
- 阅读/听力深度复盘后，交给相应复盘 Skill 执行一项微练习。
- 口语回答或写作初稿完成后，交给 `$ielts-speaking-coach` 或 `$ielts-writing-review` 反馈。
- 词汇主动回忆完成后，如实总结本轮表现；网站没有词汇复习结果写入接口。

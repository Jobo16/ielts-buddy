# 每周学习复盘

> 当前任务需要本方法时按需读取。脚本命令中的 `scripts/` 相对于本 Skill 根目录；实际运行时解析为安装目录中的绝对路径。

明确复盘周期，先利用用户给出的学习证据。需要网站记录时按 [数据接入](../api-access.md) 读取学习快照、课程进度、已完成待办及近期练习或模考；只取足够判断的数据。网站不提供词汇到期队列或学习计划代际，不能把它们当作事实来源。

1. 区分完成活动和能力证据；完成待办不等于掌握。
2. 只有两周的口径和证据可比时才比较进步。证据不足处明确标注。
3. 选出最多三个重复问题，使用 [技能分类](../skill-taxonomy.json) 的现有编码；刚产生的跨 Skill 结果按 [证据到下一步](../evidence-to-next-action/WORKFLOW.md) 接续。
4. 给出三个带完成信号的下周动作。时长以用户可用时间为准，不凭空预设。
5. 用户已要求把安排保存到网站时，直接调用 `ielts_study_todos_create`；若只是要求建议则只输出建议。已有待办需要调整时，先读取精确 id 再更新。

```text
周期：<开始日期> 至 <结束日期>
有效进展：<可核对的证据>
继续修复：<最多三个问题>
证据不足：<尚不能判断的领域>
下周动作：<三个任务，各含完成信号>
```

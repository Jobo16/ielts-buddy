# 跨 Skill 交接

本地 Agent 读取证据、判断优先级并设计下一动作；IELTS Buddy 只保存题库、练习、词汇、事件和用户已确认的计划数据。

| 上游产物 | 可读取的事实 | 本地 Agent 的下一动作 | 不应自动发生的写入 |
| --- | --- | --- | --- |
| 已提交的阅读/听力 session | `ielts_review_read_snapshot` 的正确性、作答、答案 key、题目与按需材料 | 一道精读/精听微练习，或回到浏览器复练一组精确题 | 把一次错误写成能力结论；自动加入词汇本 |
| 四步精读 / 逐句精听 | 已定位的证据桥、可证实错因、即时重测结果 | 一项明确的复练或主动回忆 | 把未经回答的复练算作掌握 |
| 词汇练习 | `ielts_vocabulary_search` 返回的已保存内容与本轮实际回答 | 一项用户要求的词块回忆 | 自动收集所有生词或虚构复习结果 |
| 口语覆盖图 | 精确 cue card、故事卡状态、覆盖缺口 | 一题 Part 2 输出或一个 Part 3 追问 | 把覆盖比例当成考题预测或口语分数 |
| 口语反馈 | 原回答或转写、局部自然改写、可复用词块 | 学习者确认后保存 2–4 个表达，或完成一次主动回忆 | 自动保存所有表达；把保存当作掌握 |
| 写前规划 | 题型、必须回应、提纲与待确认事实 | 完成一篇初稿或一个主体段 | 把提纲当成写作能力证据 |
| 写作批改 / 二改 | 原文引用、局部问题、修复状态与本地评分参考 | 一项重写目标、微练习，或学习者确认后保存 3–5 个表达 | 自动收集全部改写；将 AI 分数当官方成绩或自动宣称进步 |

## 证据强度

- `已证实`：客观判分结果，或有具体原文/作答证据的本地 review。
- `待验证`：一次偶发错误、覆盖缺口、学习者主观感受或尚未提交的草稿。
- `未知`：没有近期可核对材料；先安排最小诊断，而不是判为薄弱。

## 待办写入

用户明确要求安排或保存时直接写入；只讨论方案时返回建议。

1. 修改已有事项时，用 `ielts_study_todos_search` 定位真实 id；已知精确 id 时直接使用，不要求额外读取。
2. 新事项使用 `ielts_study_todos_create` 的 items 数组；title 必填，note、date、time、wechatEnabled 和真实 contentRef 可选。日期和时间均按 Asia/Shanghai。
3. 关联题目时复用检索结果的 `contentRef`（kind="question_part"）；普通站外学习无需关联。
4. 修改使用 `ielts_study_todos_update`，id 与待修改字段位于同一层；删除使用 `ielts_study_todos_delete`。
5. 只在用户明确说已完成时设置 status="done"；打开内容或提交练习不自动改变待办状态。

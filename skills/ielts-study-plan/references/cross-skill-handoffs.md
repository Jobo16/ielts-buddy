# 跨 Skill 交接

本地 Agent 读取证据、判断优先级并设计下一动作；IELTS Buddy 只保存题库、练习、词汇、事件和用户已确认的计划数据。

| 上游产物 | 可读取的事实 | 本地 Agent 的下一动作 | 不应自动发生的写入 |
| --- | --- | --- | --- |
| 已提交的阅读/听力 session | `ielts_practice_read_review` 的正确性、作答、答案 key、题目与按需材料 | 一道精读/精听微练习，或回到浏览器复练一组精确题 | 把一次错误写成能力结论；自动加入词汇本 |
| 四步精读 / 逐句精听 | 已定位的证据桥、可证实错因、即时重测结果 | 一项明确的复练或主动回忆 | 把未经回答的复练算作掌握 |
| 词汇练习 | `ielts_vocabulary_progress` 与卡片回答的 `again/hard/good` | 到期词卡或一项来源明确的词块回忆 | 自动收集所有生词或虚构复习结果 |
| 口语覆盖图 | 精确 cue card、故事卡状态、覆盖缺口 | 一题 Part 2 输出或一个 Part 3 追问 | 把覆盖比例当成考题预测或口语分数 |
| 写前规划 | 题型、必须回应、提纲与待确认事实 | 完成一篇初稿或一个主体段 | 把提纲当成写作能力证据 |
| 写作批改 / 二改 | 原文引用、局部问题、修复状态与本地评分参考 | 一项重写目标或微练习 | 将 AI 分数当官方成绩或自动宣称进步 |

## 证据强度

- `已证实`：客观判分结果，或有具体原文/作答证据的本地 review。
- `待验证`：一次偶发错误、覆盖缺口、学习者主观感受或尚未提交的草稿。
- `未知`：没有近期可核对材料；先安排最小诊断，而不是判为薄弱。

## 计划写入

先输出一个任务草案，再请求明确确认。确认后只使用数据型计划写入：

1. 读取现有计划和任务；不能猜测要更新哪一个。
2. 新任务使用 `ielts_study_plans_create` 的 `kind="one_time"`，传入本地 Agent 已确定的 `title`、`goal`、`dueAt` 和可选的精确 `websiteEntry`。
3. `websiteEntry.type="practice"` 只能使用学习者已经选定的精确题库 Part；没有精确题目时省略它或使用可信工作台入口。
4. 只在用户明确说“写入”“加入计划”“保存这个任务”等之后调用写工具。拟定任务、聊天建议和学习事件都不是计划写入。
5. 标记完成、改期或删除时，先读取并取得精确 `planId` 与任务 `id`，再根据用户明确指令调用更新工具。

不要调用 `kind="structured"` 的计划创建：它会让服务端自行生成任务，违背本地 Agent 决定训练内容的边界。

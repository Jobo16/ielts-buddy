# 证据到下一步

> 这是可选推荐用法，不是 Skill 接口契约或强制执行要求。只有用户要求采用该用法时才读取和使用。

## 目标

把刚完成的学习结果变成一个可执行、可验证的下一任务。先解释依据，再给任务草案；只有用户明确确认后才写入 IELTS Buddy 计划。

## 读取最小证据

1. 优先使用当前对话中刚产生的产物：已提交 session、精读/精听结论、词汇卡结果、口语覆盖图、写作提纲或批改报告。
2. 若是阅读或听力 session，先调用 `ielts_practice_read_session` 确认已提交，再调用 `ielts_practice_read_review`，默认 `scope="incorrect"`、`includeMaterial=false`。
3. 需要了解已有承诺时，读取 `ielts_study_plans_list` 或 `ielts_study_plans_next_actions`；它们只返回用户已有任务，优先顺序仍由本地 Agent 和证据决定。
4. 只有当前决策依赖长期历史时，读取本地学习镜像或 `ielts_learning_pull_events`。没有证据时转入最小诊断，不臆测薄弱项。
5. 按 [跨 Skill 交接](../references/cross-skill-handoffs.md) 判断哪些结果能作为证据。

## 选择规则

按以下优先级只选一个动作：

1. 已到期或上次回答为 `again` 的复习；
2. 有明确错题证据、且能在本次完成的精读/精听修复；
3. 已开始但未完成的学习任务；
4. 口语覆盖图中的一个缺口或需要切换角度的 cue card；
5. 写作提纲对应的一篇初稿或一个主体段；
6. 证据不足时的最小诊断。

不要把单次错误、提纲完成或任务打开当作能力变化。词汇任务必须源自已保存的词或用户明确要求收录的词。

## 任务草案

每次输出：

```text
依据：<一个可核对事实；没有则写“证据不足”>
现在做：<单一动作>
做法：<最多三步>
完成标准：<可带回来的答案、session、草稿或录音转写>
预计投入：<用户给出的时间，或“不预设”>
```

例子：

- 阅读错题 → “用本次第 6 题完成一次证据桥微练习，并重做定位。”
- 听力拼写错 → “回放答案附近片段，先预测单复数，再独立拼写答案。”
- 口语可调整题 → “用同一故事回答下一张 cue card，并在开头明确切换叙述角度。”
- 写作规划 → “按已定的 P1 论点写一个完整主体段，保留例子与结果句。”

## 写入计划

任务草案后，如果用户没有明确要求保存，直接等待完成结果，不调用任何计划写工具。

用户明确确认保存时：

1. 先确认任务标题、到期时间，以及是否需要提醒；缺少 `dueAt` 时询问，不自行假设。
2. 读取 [跨 Skill 交接](../references/cross-skill-handoffs.md) 的“计划写入”约束。
3. 调用 `ielts_study_plans_create`，仅使用 `kind="one_time"` 和本地 Agent 已确定的精确字段。
4. 有精确题目时才附上 `websiteEntry.type="practice"`；普通精读、写作和口语任务可以不附入口。
5. 返回写入后的真实任务，不声称未验证的训练已经完成。

不要因生成了任务草案而写入 `ielts_learning_push_events`。只有客观作答、用户提交的输出或本地 review 的实际结果才可以形成学习证据。

## 完成后的交接

- 浏览器客观题提交后，交给 `$ielts-practice` 的结果复盘，再回到本工作流。
- 阅读/听力深度复盘后，交给相应复盘 Skill 执行一项微练习。
- 口语回答或写作初稿完成后，交给 `$ielts-speaking-coach` 或 `$ielts-writing-review` 反馈。
- 词汇主动回忆完成后，按真实 `again/hard/good` 写入词汇复习结果。

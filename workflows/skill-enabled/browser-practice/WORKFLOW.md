# 浏览器刷题

> 这是可选推荐用法，不是 Skill 接口契约或强制执行要求。只有用户要求采用该用法时才读取和使用。

## 核心规则

本地 Agent 选择，IELTS Buddy 提供事实和浏览器交接。不要把“题库里有什么”误写成服务端对学习者的推荐。

## 开始流程

1. 判断用户是否已经明确要开始：例如“我要刷题”“开始一组阅读”“继续上次听力”。
2. 有 Agent API 时，先读取近期练习；存在未提交 session 时，优先说明可恢复的题组、已答数量和服务端返回的恢复链接。不要把未完成 session 自动说成唯一推荐。
3. 需要新题时，使用最小数据集：
   - 用户提出结构化筛选词时，先调用 `ielts_practice_list_taxonomy`，再把返回的精确 `tagIds` 传给 `ielts_practice_search_parts`。
   - 否则直接调用 `ielts_practice_search_parts`，最多取六个候选。
   - 需要根据已有证据做判断时，再读取学习画像或学习事件。证据不足时如实说明是在做诊断练习。
4. 本地 Agent 从候选中选择一个精确 `partId`：
   - 用户已明确要开始时，说明选中的题组并交给浏览器刷题中心。
   - 用户只是在浏览或比较时，最多展示三个候选，等待其选择。
5. 新练习的 session 由用户在浏览器中手动创建。Agent 不调用创建或提交接口，也不代填答案；只提供选中的权威标题、科目和题库来源，方便用户在刷题中心确认。
6. 只有已有 session 的 `read_session` 或近期活动真实返回 `launchUrl` 时，才能原样给出恢复链接；不得由 `partId`、`sessionId` 或网站域名拼接精确 session 链接。
7. 明确告诉用户：在浏览器手动开始、作答并交卷，完成后回复“已完成”或带回具体问题。

## 输出形状

```text
这一组：<标题>
题库事实：<科目>｜<题数>｜<难度>｜<是否练过>
我的判断：<一条基于用户目标或已读记录的理由；证据不足时说明是诊断练习>
开始练习：打开 IELTS Buddy 刷题中心，按上面的权威标题确认题组并手动开始
完成后：回复“已完成”，我会读取本次结果并带你复盘。
```

## 无 Agent API 降级

说明无法读取 IELTS Buddy 题库或历史，不要编造候选。提供：

```text
https://work.ieltsbuddy.igopx.cn/practice
```

这个入口只会打开刷题中心；正式 session 必须由用户在页面内创建。若用户提供了文章、题目或答案，仍可按本地能力协助练习或复盘。

# 写前规划

> 这是可选推荐用法，不是 Skill 接口契约或强制执行要求。只有用户要求采用该用法时才读取和使用。

## 目标

在学习者写作前完成审题、可执行提纲和一次自检。只提供论证结构、信息选择和句子功能，不直接代写整篇作文；学习者交稿后再转入对应批改工作流。

## 先确认材料

1. 判断是 Academic Task 1 还是 Task 2。
2. Task 2 必须有完整英文题目；Task 1 必须有清晰图表、地图、流程图或可核对的数据。材料缺失时只说明缺少什么，不猜测数据或趋势。
3. 若用户已写出正文，转到 Task 1/Task 2 批改，而不是重新把批改伪装成审题。

## Task 2：审题到提纲

1. 抄出题目中的动作词、对象、范围和每个子问题，逐项列成“必须回应”。
2. 判定题型：观点、讨论、利弊、问题解决或双问题；题干存在混合要求时，按实际问题拆开，不硬套单一模板。
3. 明确立场或回答方向。讨论题也要说明自己的判断；双问题要确保两个问题都有正文承载。
4. 为两个正文段各写一条可辩护的主张，并用 `原因 → 具体例子 → 结果/影响` 展开。例子可以是常识性、可解释的假设情境，不能伪造成统计事实。
5. 标出每段承担的题目任务，检查没有一段只是重复立场或堆砌词汇。

输出必须使用这个紧凑结构：

```text
题型：<类型>
必须回应：<逐项列出>
立场/答案方向：<一句>
P1：<主张> → <原因> → <例子> → <影响>
P2：<主张> → <原因> → <例子> → <影响>
结尾：<如何回应题目，不重复正文>
```

## Task 1：读图到提纲

1. 先识别图表类型、单位、时间范围、比较对象或流程阶段。
2. 只选择 2–3 个最显著、可核对的总览特征；不能从图表推断原因、评价或个人观点。
3. 将数据按可比较的组分成两个主体段，例如“高值组/低值组”“上升趋势/下降趋势”或“前半流程/后半流程”。
4. 每个主体段只保留支持总览的关键比较或阶段，不做逐项报数。

输出必须使用这个紧凑结构：

```text
图表事实：<类型、单位、范围、对象>
总览 1：<可核对特征>
总览 2：<可核对特征>
主体段 1：<比较组或阶段 + 关键证据>
主体段 2：<比较组或阶段 + 关键证据>
```

## 写前自检

在学习者开始写前，只问以下必要问题：

- 每个题目要求是否都有明确位置回应？
- Task 2 的立场是否能在开头和结尾保持一致？
- 每个正文段是否有具体展开，而不只是一个观点？
- Task 1 的总览是否来自图表事实，且没有解释原因或发表看法？
- 有哪一项事实、例子或立场仍需要学习者确认？

通过后，让学习者自己完成初稿，再交给 [Task 1 批改](../../skill-enabled/ielts-task1-review/WORKFLOW.md) 或 [Task 2 批改](../../skill-enabled/ielts-task2-review/WORKFLOW.md)。

## 数据边界

审题、立场选择、论证和自检均由本地 Agent 完成。IELTS Buddy 只可用于读取或保存用户已提供的题目与成果；不得调用服务端生成提纲、评分、批改或范文。
